# Heovose Admin 系统设计与功能规范白皮书

本手册定义了 Heovose 管理后台的视觉语言、交互标准及核心业务逻辑，旨在确保系统的长期可维护性、视觉一致性及操作稳定性。

---

## 1. 视觉语言规范 (Visual Identity)

### 1.1 圆角标准 (Border Radius)
*   **容器级 (Container)**: 统一使用 `rounded-2xl` (16px)。适用于页面卡片、主要弹窗容器。
*   **内嵌级 (Internal)**: 统一使用 `rounded-xl` (12px)。适用于列表项、次级容器、图片容器。
*   **组件级 (Component)**: 统一使用 `rounded-lg` (8px)。适用于 Input, Select, Button, Badge。
*   **严禁使用**: 任何超过 `24px` 的超大圆角（如 `rounded-[2.5rem]`），以维持专业生产力工具的干练感。

### 1.2 空间布局 (Layout & Spacing)
*   **全局边距**: 页面主容器内边距统一为 `p-6`。
*   **高度对齐**: 
    *   顶部导航栏: `h-16`。
    *   标准表单控件 (Input/Select/Button): `h-10` 或 `h-11`。
*   **编辑器策略**: 内部编辑区域（如详细介绍）采用 `calc(100vh - 280px)` 等动态计算方式，最大限度利用垂直空间，禁止出现多重嵌套滚动条。

## 2. 核心功能逻辑 (Business Logic)

### 2.1 产品编辑器 (Product Editor)
*   **ID 生成**: 
    *   仅在“发布新产品”且“选择分类”时触发。
    *   格式: `分类名称前缀_时间戳末尾` (小写并处理空格)。
*   **AI 智译**: 
    *   基础信息: 点击“AI 智译全量”必须同时翻译并回填“产品名称”与“产品简介”。
    *   技术规格: 必须保留行级 AI 翻译按钮。
*   **数据稳定性**: 
    *   技术规格行必须携带隐藏的 `uid`。
    *   删除、新增或重新排序操作不得破坏规格项与翻译词条的 ID 映射关系。

### 2.2 图库管理系统 (Gallery Management)
*   **框选机制 (Marquee)**: 
    *   仅在背景空白处触发。
    *   必须相对于 `.select-none` 容器进行坐标计算，不受滚动干扰。
*   **冲突处理策略**:
    *   **重命名**: 若文件名冲突，自动追加随机后缀，保留原标题。
    *   **覆盖**: 若文件名冲突，强制复用原有 ID，执行覆盖写入以同步刷新全站引用。
*   **批量操作**: 
    *   悬浮控制条必须设置 `z-index: 200` 以上，固定在顶部导航下方。
    *   执行搜索或筛选操作时，必须清空 `selectedIds` 以防误删不可见项。

### 2.3 翻译资产管理 (Translations)
*   **域隔离**: 
    *   业务内容 (`prod_`, `cat_`, `adv_`): 必须支持语义查重及引用合并。
    *   系统文案 (`ui_`, `nav_`): 独立维护。
*   **引用安全**: 删除操作前必须检测 `referenceMap`，提示用户该词条是否正被产品或分类引用。

## 3. 技术合规性 (Compliance)

### 3.1 无障碍 (Accessibility)
*   **Dialog 标准**: 所有 `DialogContent` 内必须显式包含 `DialogTitle` 和 `DialogDescription`。若视觉上不需要显示，必须使用 `sr-only` 类名进行隐藏。

### 3.2 性能标准
*   **实时更新**: 所有的写入操作（setDoc, updateDoc, deleteDoc）必须使用 `non-blocking` 模式，即不使用 `await` 阻塞 UI，优先更新本地缓存以保证录入丝滑。
*   **引用缓存**: 使用 `useMemoFirebase` 稳定 Firestore 引用，严禁在 `useEffect` 依赖中直接创建字面量对象，防止无限渲染。

---

## 4. 变更管理规范 (Change Management)

### 4.1 授权机制
*   **先请示后执行**: 任何对现有业务逻辑的修改、或对白皮书条款的更新，AI Agent 必须先提交“变更摘要”并征得管理员（用户）的明确同意。
*   **版本追溯**: 每次通过授权的更新必须同步修正白皮书的“最后更新日期”，并在对话历史中保留变更说明。
